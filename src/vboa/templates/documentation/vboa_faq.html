VBOA FAQ

What roles are available and what can each role access?

VBOA uses role-based access control through Flask-Security-Too and the UBOA user database. Each view is protected by the @roles_accepted() decorator with a specific set of allowed roles.

  • administrator: full access, including user management (create, import, export, delete users) and BOA service control (orchestrator, cron, scheduler).
  • service_administrator: BOA service control, health monitoring, ingestion control and all operational views except user management.
  • operator: operational tasks such as ingestion control, scheduling, health monitoring and service control.
  • analyst: data analysis views including EBOA navigation, reporting, alerts and screenshot saving.
  • operator_observer: read-only access to operational and analysis views (no write operations).
  • observer: read-only access limited to the dashboard and documentation pages.

The observer role is the most restricted: it cannot access EBOA navigation, reporting, scheduling, ingestion control or alert management views.

How does the VBOA_TEST environment variable work?

When the environment variable VBOA_TEST is set to TRUE, VBOA disables authentication and authorization checks. The custom @auth_required() and @roles_accepted() decorators become no-ops, allowing automated tests to access protected endpoints without logging in.

In test mode, session cookies are also configured without the secure flag so that tests can run over plain HTTP. This mode must never be enabled in production deployments.

How do I save a page screenshot as a report?

Every VBOA page includes a Save screenshot of this page as a report button in the page actions bar. Clicking it captures the current HTML content of the page and sends it to the POST /save-screenshot endpoint.

The back-end stores the captured content as an RBOA report with manual generation mode. Saved screenshots can later be browsed and opened from the Reporting navigation section.

Roles allowed to save screenshots: administrator, service_administrator, operator, analyst and operator_observer.

How do I query events programmatically through VBOA?

VBOA exposes a REST query endpoint at GET /query/. The request must include a Content-Type: application/json header and a JSON body with an events key containing the EBOA query filters. 

curl -X GET https://<host>/query/ \
  -H "Content-Type: application/json" \
  -d '{"events": {"gauge_name": "GAUGE_NAME", "limit": 10}}'

The response follows a standardized format with a response object (status and message) and a data object containing the matched events with event records and annotations. Invalid filters return HTTP 400 with an error description.

Note that this endpoint does not require authentication, making it suitable for service-to-service integration when network access is restricted by other means.

What are sliding time windows in control dashboards?

Several VBOA control dashboards — BOA Health, Ingestion control, Reporting control and General view of alerts — support sliding time windows. Instead of querying a fixed date range, the sliding window continuously moves forward to show the most recent activity within a configurable duration.

This is useful for operational monitoring where the operator needs a live view of recent ingestions, report generations, health events or alerts without manually updating the time filters on each refresh.
