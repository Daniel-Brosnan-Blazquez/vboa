VBOA documentation

Introduction

VBOA (Visualization for Business Operation Analysis) is the web-based front-end for the BOA (Business Operation Analysis) suite. It provides operators and analysts with interactive tools to query, visualize, monitor and manage operational data stored by EBOA and related BOA components.

VBOA is designed as a modular Flask application with a role-aware navigation interface. Each functional area — event navigation, reporting, scheduling, ingestion control, health monitoring and user administration — is exposed as a dedicated view that integrates with the corresponding BOA backend service.

Purpose and scope

VBOA targets operational environments where business data must be explored in near real time, correlated across sources and shared through reports and dashboards.

  • Interactive querying and navigation of EBOA events, annotations, sources, gauges and explicit references.
  • Geospatial visualization of event geometries and Earth observation data using OpenLayers and Cesium.js.
  • Report generation, browsing and execution through RBOA integration.
  • Task scheduling visualization and simulation through SBOA integration.
  • System health, ingestion and reporting control dashboards with sliding time windows.
  • Centralized alert browsing with severity filtering across all BOA entities.
  • Role-based access control for administrators, operators and analysts.
  • REST API and Prometheus metrics endpoints for external integrations and observability.
  • Page screenshot capture stored as RBOA reports for documentation and sharing.

Architecture overview

VBOA follows a classic three-tier architecture: a Python Flask back-end, a Jinja2/Bootstrap front-end and direct database access to the BOA subsystem databases.

Back-end stack

  • Web framework: Flask with modular blueprints for each functional area.
  • Security: Flask-Security-Too with email and username authentication, password hashing and session management.
  • User management: UBOA datamodel for users, roles and audit tracking.
  • Data access: direct integration with EBOA, RBOA, SBOA and UBOA engines and query APIs.
  • WSGI server: Gunicorn with SSL support for production deployments.

Front-end stack

  • Templates: Jinja2 with Bootstrap (SB Admin 2 theme).
  • JavaScript: ES2015+ bundled with Webpack and Babel; jQuery for DOM and AJAX.
  • Visualization: Cesium.js (3D geospatial), OpenLayers (2D mapping), Chart.js (charts), vis.js (timelines and networks), DataTables (tables).
  • Build: npm and Webpack produce dist/bundle.js and dist/styles.css.

BOA integration

  • EBOA: event, annotation, source and alert querying; manual data treatment; re-ingestion and deletion.
  • RBOA: report storage, retrieval, execution and screenshot reports.
  • SBOA: scheduled task navigation and simulation.
  • UBOA: user accounts, roles, import and export.

Navigation and modules

The VBOA side panel groups functionality by operational area. Access to each section depends on the authenticated user's role.

  • Users management (administrator): browse, import and export UBOA users and roles.
  • BOA management (administrator, service_administrator, operator): switch the orchestrator, cron and scheduler on or off.
  • BOA Health (administrator, service_administrator, operator): complete health dashboard and alert-focused view.
  • BOA Scheduler (all roles except observer): simulate and navigate scheduled tasks.
  • Ingestion control (all roles except observer): manual ingestion, complete view, ingestion errors and alerts.
  • EBOA navigation (all roles except observer): query and browse EBOA entities.
  • General view of alerts (all roles except observer): cross-entity alert overview with sliding time window.
  • Reporting navigation (all roles except observer): browse and open RBOA reports.
  • Reporting control (all roles except observer): execute reports, monitor status, errors and alerts.
  • Earth observation (when enabled): 3D orbit tracking and swath visualization.
  • Documentation: EBOA and VBOA design documentation and FAQ pages.

Every page includes a Save screenshot of this page as a report action that stores the current view as an RBOA report for later retrieval.

EBOA navigation

The EBOA navigation module is the primary interface for exploring stored operational data. It supports querying events, annotations, sources, gauges, explicit references, DIM signatures and event records (ERs), with pagination, JSON export and map visualization for geometries.

Key capabilities include:

  • Advanced filtering by temporal range, geometry, gauge, DIM signature, explicit reference and event values.
  • Event alert browsing with severity and generator filters.
  • Source management: download, re-ingest and delete sources.
  • WKT geometry export for map display on OpenLayers.

Geospatial visualization

VBOA provides two different geospatial views using OpenLayers maps and Cesium.js.

Reporting and analytics

The reporting modules integrate with RBOA to browse, execute and monitor analytical reports. Reports can contain charts, tables, widgets and saved page screenshots.

Reporting control provides:

  • On-demand report execution.
  • Sliding-window monitoring of report generation status.
  • Dedicated views for reporting errors and alerts.
  • Report re-generation and removal operations.

System health monitoring

The BOA Health dashboard aggregates status indicators from across the BOA infrastructure. Operators can inspect component availability, review health alerts and adjust the sliding time window to focus on recent activity.

Service management endpoints allow authorized users to check and switch the orchestrator, cron daemon and SBOA scheduler on or off directly from the navigation panel.

Task scheduling

The BOA Scheduler module connects to SBOA to visualize and simulate scheduled operational tasks. The simulate view loads an agenda from a given reference time and shows the expected execution sequence. The navigate view provides tabular browsing of scheduled tasks.

Alert management

VBOA surfaces alerts at multiple levels. The general view of alerts provides a unified cross-entity overview with severity filtering and a configurable sliding time window. Entity-specific alert views are available within EBOA navigation, ingestion control, reporting control and BOA health.

Data ingestion control

Ingestion control lets operators monitor the data ingestion pipeline, trigger manual ingestion of files, review ingestion errors and inspect ingestion-related alerts. Configuration files such as triggering.xml and the orchestrator configuration can be downloaded for inspection.

User management and security

VBOA uses Flask-Security-Too backed by the UBOA user database. Authentication supports email-based and username-based login with optional remember-me persistence.

Supported roles and typical access:

  • administrator: full access including user management and BOA service control.
  • service_administrator: service management, health, ingestion and operational views.
  • operator: operational tasks including ingestion, scheduling and health monitoring.
  • analyst: data analysis, reporting and event navigation.
  • operator_observer: read-only access to operational and analysis views.
  • observer: read-only access to the dashboard and documentation.

Security configuration highlights:

  • HTTP-only session cookies; secure cookies enforced in production.
  • Password change enabled without automatic change emails.
  • Custom @auth_required() and @roles_accepted() decorators with test-mode bypass.

REST API and integrations

VBOA exposes programmatic interfaces for external systems and monitoring tools.

Query API

The GET /query/ endpoint accepts a JSON payload with an events key containing EBOA query filters. It returns matching events with event records and annotations in a standardized JSON response. 

curl -X GET https://<host>/query/ \
  -H "Content-Type: application/json" \
  -d '{"events": {"gauge_name": "GAUGE_NAME", "limit": 10}}'

Metrics endpoint

The GET /metrics/ endpoint publishes Prometheus-compatible metrics read from the BOA metrics files. This supports Grafana dashboards and alert rules.

Screenshot API

The POST /save-screenshot endpoint stores the HTML content of the current page as an RBOA report. It is used by the save-screenshot button available on every page.

Service management

Endpoints under the service management blueprint allow checking and toggling the orchestrator, cron and scheduler processes. These are invoked from the BOA management section of the navigation panel.

Full Stack Application: EBOA + VBOA

VBOA is the visualization and operational interface layer of the BOA stack. It is designed to work seamlessly with EBOA, which provides the back-end data storage and management engine.

The combined EBOA + VBOA stack delivers:

  • EBOA (Backend): data storage, validation, ingestion orchestration and query engine built on PostgreSQL.
  • VBOA (Frontend): interactive web application for visualization, analysis, monitoring and administration.

Most deployment-specific behaviour is driven by configuration rather than code changes. EBOA defines the data model and ingestion rules; VBOA exposes the resulting data through configurable views, filters and reports.

For detailed information about the EBOA data model, ingestion strategies and Python API, refer to the EBOA design documentation.

Configuration and environment

VBOA behaviour can be adjusted through environment variables and resource files.

  • VBOA_TEST (TRUE/FALSE): disables authentication and authorization for automated testing.
  • VBOA_DEBUG (TRUE/FALSE): enables Flask debug mode and the debug toolbar.
  • Secret key: loaded from {resources_path}/web_server_secret_key.txt or auto-generated on first start.

Production deployments typically use Gunicorn behind a reverse proxy with HTTPS. Docker and Podman compose files are provided for containerized deployment on Rocky Linux 9.

Prometheus integration

VBOA publishes BOA metrics through a Prometheus-compatible endpoint at /metrics/. Metrics are collected from the BOA infrastructure and exposed as plain text for scraping by Prometheus, enabling Grafana dashboards and alert rules based on operational indicators.
